# The original pipeline against this branch

12 October 2026. The question this answers: **against the code that was live
before any of this work, where is the draft pipeline better, where is it the
same, and where is it worse?**

Every number here comes from `scripts/audit-probe/ab-2026-10-12/`, which holds
the four eval runs, the four graded runs, the pipeline file hashes and the two
scripts that produced them. Reproduce the tables with:

```bash
node scripts/audit-probe/ab-2026-10-12/compare.mjs \
  scripts/audit-probe/ab-2026-10-12/base-full.json \
  scripts/audit-probe/ab-2026-10-12/new-full.json \
  scripts/audit-probe/ab-2026-10-12/g-base-full.json \
  scripts/audit-probe/ab-2026-10-12/g-new-full.json
```

### Voice

`zeroContractionPre` — drafts the model wrote with **no contraction at all** —
was **16 of 16 in both profiles** at base and is **0 of 16 (full)** and **1 of
16 (sparse)** now. The base pipeline's emails only sounded human because the
*reviewer* put the contractions in afterwards; the drafter now writes them
itself. That is also why reviewer workload fell: `problems` 65 → 53 (full) and
62 → 43 (sparse).

## 3. The same

- **`cv_recital` has not moved at all.** 15 of 16 full-profile emails and 14 of
  16 sparse carry a credentials paragraph nobody asked for, in **both** arms.
  This was a deliberate non-fix and the A/B justifies it: all 15 full-profile
  emails carrying it get a reply anyway.
- **Length discipline.** `overCeilingPre`, `overCeilingPost` and
  `overCeilingWordsPost` are 0 in all four arms. Nothing has ever gone over a
  ceiling; nothing does now.
- **Safety.** `blockedLanguage` 0 in all four arms, `lintForStudentPost` 0 in

- **`cannedResumePre/Post`** 13 and 9, identical in both arms. The resume
  mention is formulaic in both.
- **Latency, in aggregate.** See below.

## 4. Worse

**1. The draft call is slower, by about half a second to a second.**
`draftMsMean` +1,342 ms (full) and +565 ms (sparse) — the only "worse" metric
that moves the same way in both profiles, so it is the one to believe. The
prompt grew: format coherence, the connection rewrite and the new `GAP_RULES`
paragraph all cost tokens the drafter has to read.

**2. End-to-end latency is noise, not a win and not a loss.** `totalMsMean`
went **+2,542 ms on full profiles and −1,981 ms on sparse** — opposite signs
on the same change, from the same transport, at n=16 each. Anyone quoting
either number alone is quoting noise. This is consistent with what the handoff
already said: **latency is unchanged, and no idea for improving it has ever
survived measurement.** It remains unmeasured on the production path, which has
`effort`, `thinking` and fast-mode that the CLI rig does not.

**3. One contraction fewer per finished email, on full profiles only.**
`contractionsPostMean` 3.31 → 2.31. Outside the ±0.20 noise band for n=16 — but
the sparse arm moved +0.125, inside it. One arm worse, one arm flat: probably
noise, recorded rather than explained away. If it is real it is the reviewer no
longer adding contractions to a draft that already has some.

**4. `lintForReviewPost` 1 → 2 (full) and `problemsNeedsStudent` 1 → 2
(sparse).** One email each. Below anything this corpus can resolve.

## 5. The one email that was still bad — fixed the same day

Scenario **819** — sparse `redirect_sequence`, closing the loop after a
redirect — was the single off-putting email left in either new arm, and the
judge named exactly why:

> The most useful part was **[one thing you learned from Ben]**.

The same scenario carried the same defect in the 11 October human read
(*"a thank-you with '[one specific thing from Ben's advice]' as its middle
paragraph"*). **Two runs, two days apart, same scenario, same failure** — which
is what a reproducible bug looks like, and is the difference between this and
the `keep_in_touch` finding retired in D52.

Not a plumbing bug. The sparse student answered three fields, and
`redirectDetail` — the one field that holds what came of the conversation — is
**optional**, so it was blank and the drafter went to `GAP_RULES`.

**The demand was in two places, and checks 1–3 of `format-facts-test` read
neither of them.** `redirect_sequence`'s close-the-loop `promptNote`, and
**Volume V section 17's format step** — the combination format, which refines
the per-type format and which nothing had ever audited. Both now carry their own
branch condition, the same pattern `PROMPT-COHERENCE.md` applied to
`offer_extension`, `coffee_in_person_reply` and `thank_you_event`, and both say
it explicitly: never a bracketed marker there, because the sentence reads
perfectly without one.

### What the fix measured

Both profiles re-run and re-graded on the fixed code, 16 of 16 drafted, 0
errored, pipeline hashes unchanged across the run. Runs in
`scripts/audit-probe/ab-2026-10-12/after-819/`.

| | before the fix | after |
|---|---|---|
| **819** | `off_putting` | `would_ignore`, writing around the gap |
| **brackets in all 32 emails** | 1 | **0** |
| sparse, emails that ask | 8 of 9 would reply | **9 of 9** |
| sparse, ask only if named | 3 of 4 landed | **4 of 4** |
| **off-putting, both profiles** | 1 | **0** |

`would_ignore` is the right verdict, not a consolation prize: the close-the-loop
branch's own note says *"No new ask"*, so `ASK_SHAPE` scores it on landing. The
email went from harming its sender to a warm note that is correctly ignored.

### And the noise floor, measured at last

The full-profile arm is a **near-control** for this change: it holds no
`redirect_sequence` lead at all, and only 2 of its 16 emails can see either
edited line. Its verdicts are identical before and after — **15 of 15 would
reply, 0 off-putting** — which is the evidence that nothing was traded away.

Its *metrics* are not identical, and that is the useful part. **21 of 58
metrics moved when near-identical code was run twice**, in both directions:
`contractionsPostMean` +0.375, `problems` +4, `repeatedSentencesPost` +1,
`overclaims_connection` 0 → 2, `cv_recital` 15 → 13, `awkward_phrasing` 4 → 1.
This is the floor the handoff's §9 noise bands only covered four metrics of, and
it is the bar any future single-arm claim has to clear. The earlier A/B that was
invalidated because "the experiment moved 31 of 58 metrics while a control moved
28" now has a second data point and the same lesson.

### Still open: the other five

The same 18 Volume V sections hold **five more** steps that insist on a specific
fact with no branch condition — S2, S4, S6, S10, S11, S12 in
`email-examples-v5.json`. Whether each one's underlying field is required has
not been checked. The new check in `format-facts-test` asserts the 819 instance
exactly rather than adding a heuristic with five unexamined exemptions, which is
the failure mode that file already warns about in its own KNOWN list.
