# The rig and production were on different models — and Sonnet 5.5 is fine

13 October 2026. Two findings, the second only visible because of the first.

Runs: `scripts/audit-probe/sonnet-55-2026-10-13/`.

---

## 1. Every CLI measurement this session described a model production does not run

`scripts/draft-cli-eval.ts` had `const DEFAULT_MODEL = "claude-sonnet-5-5"`,
with no comment, while `lib/model-registry` shipped `claude-sonnet-5`. The
saved runs record it plainly — `sweep87-2026-10-12/all87.json` says
`meta.model: claude-sonnet-5-5`.

**What survives.** Every A/B's *relative* result. Both arms of a comparison used
the same model, so a prompt change's measured effect is still its effect: 11 of
24 → 24 of 24 on replies, 14 → 0 off-putting, the 819 and 826 fixes, the
blanket-no-ask fix. None of that is affected.

**What does not.** The *absolute* figures. "59 of 63 ask-type emails would get a
reply" across the 87-scenario sweep was **Sonnet 5.5's** output, not what a
student receives from Sonnet 5. Anywhere a number in `docs/concepts` is quoted
as the pipeline's standing quality, it is 5.5's.

**This is the fifth component found choosing a model independently of the
registry in two days**, after `DRAFT_REVIEW_CONFIG`, `help-knowledge-learn`'s
hardcoded model, `helpMessageParams` dropping effort and thinking, and
`draft-pipeline` rebuilding the thinking parameter by hand. The rig now reads
`getModelConfig("draft", "free").model`, `--model` still overrides it for an
A/B, and an overridden run says so in its output and its `--json`.

## 2. So: is Sonnet 5.5 actually better? Measured, free

Both models over the same 16 full-profile scenarios on current prompt code, one
sitting, graded blind. **Free** — the CLI rig runs on the subscription.

| | `claude-sonnet-5` (ships) | `claude-sonnet-5-5` |
|---|---|---|
| **emails that ask, would reply** | **15 of 15** | **15 of 15** |
| off-putting | 0 | 0 |
| `reads_machine_written` | 0 | 0 |
| `cv_recital` | 11 | 10 |
| `issuesPre` (own-facts, pre-review) | 17 | **11** |
| `lintCleanPre` | 10 | **14** |
| `lintForReviewPre` | 7 | **2** |
| contractions per draft, pre-review | 1.63 | **2.75** |
| guard accept rate | 0.875 | **0.938** |

**Quality is indistinguishable on the metric that matters and better on the ones
that describe how much fixing the draft needs.** 5.5's drafts arrive with fewer
own-facts problems, fewer lint findings for the reviewer, and more contractions
already in them — which is the drafter doing work the reviewer used to do.

**One number deliberately not read:** `draftMsMean` 71,120 ms against 17,044 ms,
and `reviewMsMean` 93,073 ms against 12,974 ms. The arms ran sequentially
through a shared CLI, and `audit/LATENCY-API-2026-10-12.md` already established
that CLI timings are transport rather than the paid path — the rig overstates
the review and understates the draft. The gap is unexplained and nothing here
rests on it.

## 3. What still blocks the migration, and it is not quality

`claude-sonnet-5-5` **rejects `thinking: "disabled"`**, which eleven of the
thirteen registry rows ask for. Its thinking-off mode is
`{type: "between_tools"}`, now expressible and guarded
(`ACCEPTS_BETWEEN_TOOLS`), and its effort levels are **recalibrated** from
Sonnet 5, so `effort: "low"` may not mean what it means today.

Neither of those can be measured on the CLI, which has no `effort` and no
`thinking` parameter at all. **One paid arm settles it** — about $0.43:

```bash
npx tsx --conditions=react-server --env-file=.env.local scripts/draft-live-eval.ts \
  out.md --concurrency=1 --draft-model=claude-sonnet-5-5 \
  --draft-thinking=between_tools --drafts-json=arm.json
```

against the same command without the two `--draft-*` flags as a control. Until
that runs, the constant stays on `claude-sonnet-5`: the quality case is made,
the production-path case is not.

## 4. What this does not say

- 16 scenarios, one profile, one sitting, one prompt revision.
- Nothing about Opus. `claude-opus-5-5` cannot turn thinking off at any effort
  and seven paid rows run with it off, so it remains not recommended.
- Nothing about the other eleven features. This measured the draft only; the
  recalibrated effort would land on all of them.
